# Development Update - 2026-04-02

## Focus Of The Day

We explored a stronger visual upgrade for local mode, especially the board and orb presentation, but the work was intentionally rolled back after repeated rendering and dev-runtime issues.

## What We Attempted

### 1. Slower Reaction Presentation

- experimented with slowing down the local chain-reaction flow so captures would read tile-by-tile instead of feeling instant
- also explored delaying the winner reveal so the ending would feel more visible and less abrupt

### 2. UI Stack Expansion

- tried bringing in additional visual tooling on top of the existing Next app
- this included:
  - `motion`
  - Tailwind utility usage
  - a temporary experiment with heavier visual rendering ideas

### 3. Board Visual Redesign Attempts

- explored multiple approaches for making the local board feel more premium
- tried both:
  - scene-heavy / pseudo-3D directions
  - flat board directions with glossy orb styling
- repeatedly aimed toward:
  - black premium board shell
  - cleaner grid lines
  - molecules that feel like they pop out visually

## Problems Encountered

### 1. Visual Rendering Instability

- orb clustering and positioning became unstable during multiple iterations
- in different attempts, orbs:
  - overlapped incorrectly
  - rendered outside their intended cells
  - became effectively invisible due to CSS sizing/positioning mistakes

### 2. Runtime / Dev Cache Problems

- repeated Next.js dev/runtime issues appeared during the experiment
- examples included:
  - missing chunk/module errors
  - stale `.next` state causing mismatched runtime files
  - `_document`-related chunk resolution problems during one workaround attempt

### 3. Scope Drift

- too many rendering ideas were explored in one pass
- this made the local UI harder to stabilize quickly
- the underlying gameplay logic remained sound, but the visual layer became too volatile

## Decision Taken

We reset the repo back to the clean known-good commit:

- `ecb7bbdc63cfe330df7614547542a93d7347f231`

This was done intentionally so the project would return to a stable base before trying further UI work.

## Important Learning

The main issue was not the game rules or product direction.

The issue was implementation scope:

- too many visual/rendering changes were attempted without locking a stable rendering model first
- the safe path is to keep the existing DOM board and improve it in very small steps

## Recommended Next Path

If local board visuals are revisited, use this order only:

1. keep the current DOM board structure
2. do not change render strategy or architecture
3. improve orb visuals first only
4. after orb clusters look correct, improve board shell and cell materials
5. avoid experimental 3D/canvas/particle directions until the flat premium board is already working

## Current State After Rollback

- repo is back on the stable commit listed above
- local changes from today were discarded
- workspace was left clean after reset

## Notes For Next Chat

- if local UI work resumes, start with a very small orb-only visual pass
- verify each pass in-browser before layering the next one
- if Next dev errors reappear, clear `.next/` and restart `npm run dev` before assuming app code is broken
